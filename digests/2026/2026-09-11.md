### 1. Stop babysitting coding agents — remote/headless Decode harness on Modal (Decoding AI) [HIGH]
Primary link: https://www.decodingai.com/p/coding-agents-in-remote-headless

Paul Iusztiin’s Decoding AI Lesson 6 (open-source course Building a Coding Agent From Scratch) is the highest-priority mail item for Tal this window: a concrete build of a headless, remote coding-agent harness—exactly the harness-over-model thesis. LangChain’s Terminal-Bench experiment is the motivating fact: changing only the harness (same model) moved a coding agent from ~30th into the top 5. The lesson takes Decode from a babysat TUI to (1) a CLI headless interface (`decode run "<goal>"`) that shares `build_agent()` / `AgentDeps` with the TUI but defaults to bypass permissions, makes `ask_user` a no-op, prints only the final answer, and ships full traces to Opik; (2) Modal serverless jobs so the laptop only triggers—CLI, webhook (Slack/Discord/Telegram), or nightly cron—while Modal runs `decode run` as a subprocess inside gVisor containers that scale to zero when idle; (3) parallel `decode remote attempts` that spawn N independent agents on the same feature, each pushing a `decode/<attempt>` branch (optionally with `--sandbox-mode modal` cloning `--repo` into a Modal sandbox) so a later agent can compare and forward the best PR. Design details that map to Tal’s fleet: clean separation of app layer vs serving layers (TUI / CLI / remote / upcoming evals harness); `--max-requests N` as a doom-loop guard for unattended runs (Anthropic long-running-harness failure mode); webhook returns a call ID in milliseconds via `.spawn()`; cron via `DECODE_NIGHTLY_CRON`; Ramp cited as production precedent (routing queue + session locks; ~half of merged PRs from this pattern). Extension pattern: one orchestrator headless run fans fine-tuning experiments into GPU sandboxes (`gpu="H200:4"`) while the orchestrator stays on CPU. Serverless vs hyperscaler pricing napkin favors Modal for bursty agent work (pay-idle=$0). Course next: evals harness on this same remote infrastructure.

### 2. Frontier engineering — how to work when agents write most code (Kiro; The Code / ~2k PRs practice)
Primary link: https://kiro.dev/topics/frontier-engineering/
Also: https://kiro.dev/topics/frontier-engineering/architect-not-typist/ · https://kiro.dev/topics/frontier-engineering/maximize-agent-time/ · https://kiro.dev/topics/frontier-engineering/build-for-agents/ · https://kiro.dev/topics/frontier-engineering/trust-the-boundaries/ · https://flaviocopes.com/pstack/

The Code’s “engineer ships ~2000 PRs/month” pack points at Kiro’s Frontier engineering guide as the playbook for working when agents write most of the code (the newsletter’s archive.codenewsletter.ai ID resolved to an unrelated John Ternus Apple-event tweet—use Kiro as primary). Thesis: software work has split into people who only swapped tools vs people who changed the job—frontier developers hand-write <1% of code and instead build the agent setup that builds the software; first weeks feel slower (steering files, codebase refactors, task decomposition), then compound. Ten-principle spine that matters for Tal/Grok Bot: you are the architect not the typist (write intent + acceptance criteria, not lines); maximize agent time / minimize involvement (long tasks with built-in validation, parallel agents, overnight runs—stop being a human conveyor belt of paste-error loops); build the codebase for agents (README/arch docs, tests-as-spec, module boundaries, steering files, skills, MCP—agents onboard every session); execution is cheap / direction is everything (spec-first; prototype competing designs with agents); trust the boundaries not the agent (constrain files/tools/network/credentials, then unsupervised; never give production creds casually; SAST/cred-scan/automated-reasoning as automated guardrails). The same The Code window is the Lauren Tan (@poteto) SpaceXAI / Grok Bot practice that made the 1k→2k PR/month claim concrete: open-source Cursor plugin pstack (`/poteto-mode` router over 21 principles / 22 playbooks / 23 skills; `/how` `/why` `/architect` `/arena` `/swarm` `/interrogate`; Autopilot / Orchestrate / Babysit); Dune architecture that turns review comments into red CI (ban agent-misused patterns, hard directory/process boundaries—“if you only have rules and skills, the codebase becomes garbage”); verification-over-prompting (control-glass + feature maps; “agents guess and don’t know they’re guessing”); ~600 refactor PRs as infrastructure before waking up to ~20 auto-merged PRs. Direct twin to Tal’s harness lane: make the shortest path the correct path, then multiply agents.

### 3. Connections — managed credentials + per-caller identity for Managed Deep Agents (LangChain)
Primary link: https://www.langchain.com/blog/connections-managed-credentials-and-per-caller-identity-for-managed-deep-agents
Also: https://docs.langchain.com/langsmith/python/managed-deep-agents-connections

LangChain ships Connections in Managed Deep Agents v0.7.0+: named credentials that live in the LangSmith workspace (not `.env`, not the build) and tools read at runtime by slug via `connections.get()`. Two independent axes—owner (agent-owned shared vs user-owned per-caller) × credential type (static secret vs OAuth grant)—fix the gap where one hard-coded API key answers what the agent may do but not who asked. Agent-owned secret (e.g. `mda connections create tavily-agent --secret-from-env TAVILY_API_KEY`) is right for shared capabilities like web search; rotate in LangSmith without redeploy. User-owned OAuth (GitHub in catalog + 22 other services, or bring-your-own metadata) resolves per person: `connections.get("github-issues", {"type": "user"})` pauses for grant on first/expired auth, then `create_issue` lands under the caller’s `user.login`, not a bot; private-repo search already differs per caller on the same deployment. MCP servers that self-register OAuth need only a URL (`--mcp`). Missing grants batch into one interrupt before the first model turn. Fourth cell: `--authorize` stores one shared OAuth grant for a dedicated team account. Security/harness read for Tal next to Thu’s Muse Sentinel story: credentials stay out of the model cell and out of the project; per-caller identity is a first-class connection object, not a post-hoc ACL on a service account.

### 4. Economic Scenarios for Transformative AI — Anthropic Institute explorer
Primary link: https://www.anthropic.com/institute/econ-scenarios

Anthropic’s Economics team (Korinek, Jones, Sacher, Cotter, McCrory et al.; technical report Economic Scenarios for Transformative AI, 2026) published an interactive scenario explorer that maps AI capability/adoption/autonomy/productivity/job-adjustment assumptions onto 2030 US GDP, unemployment, wages, and labor vs capital share—framed as a thinking tool, not a forecast (v1.0; omits policy responses, business cycles, demand shocks, catastrophic risks, robots). Economy = O*NET task bundles; AI can augment, automate, leave alone, or create new tasks. Three highlighted futures: modest (internet-scale impact; GDP ~+$1.6% → $34.1T; labor share ~59.4%); substantial (AI can do ~half of knowledge work by 2030, mostly autonomously, but adoption incomplete; ~2× normal growth; GDP ~+$8.3% → $36.3T; knowledge-worker wages flat, others up; capital share +3.9 pp); extreme (AI more productive than humans on vast majority of knowledge tasks, nearly all autonomous, almost no new knowledge tasks for people—likely needs recursive self-improvement + fast adoption; GDP growth ~15%/yr, economy doubles ~every 4.5 years; GDP ~+$32.4% → $44.4T; unemployment beyond typical recession; knowledge wages fall >10%; labor share collapses to ~45.2% / capital +14.8 pp; total labor income barely changed). August survey of >10k Americans: typical answers imply near-substantial (~+10% GDP, ~5% unemployment); ~10% of respondents align with extreme. Peer reviewers (Acemoglu, Autor, Restrepo, Moll, Nakamura, et al.) pushed capital-share and wage-divergence channels into the model; open critiques include no individual worker paths, whether AI-exposed occupations shrink vs grow, and understated tech-progress acceleration. Useful for Tal as macro context on recursive SI / knowledge-work automation—not a harness how-to.

## Agent memory

### Grounding Agent Memory: Environment-Probing Curation for Enterprise Agents

https://arxiv.org/abs/2609.11060

Suresh et al. argue that persistent agent memory is entering production platforms, but a post-task curator that only sees completed trajectories can preserve errors, overgeneralize, or keep stale knowledge. Their fix is environment-probing curation: give the existing asynchronous curator least-privilege, read-only world tools so it can check, scope, and refresh candidate memories before they stick—no retraining, and the task agent, retriever, memory schema, and write authority stay unchanged. In a production-like GitHub Copilot harness on the GHCP SDK, probing lifts CLBench pass rate 39%→73% and pass-discounted reward 8.60→22.60 while cutting queries 8.8→4.7 and task-agent cost $3.38→$1.68; across six APEX consulting worlds all 18 memory-vs-baseline comparisons are positive with 16–75% fewer tool calls, and probing wins best reward-per-dollar in five. Holds on Sonnet 4.6 and Opus 4.7 without schema drift. Directly actionable for Tal: treat memory writes as an auditable, environment-checked curation step—not a passive summarize-and-store after the run.

### Kernel-Managed Shared Memory for System-Wide Personalization

https://arxiv.org/abs/2609.10144

Lum and Zhang tackle the multi-agent personalization gap where context learned by one specialist stays invisible to others. They put shared memory under the agent-system kernel: specialists write structured, tagged memories, but the kernel—not the agents—owns retrieval, privacy enforcement, and prompt injection into prompts. Built on AIOS and evaluated over 1,800 trials across GPT-4o, Llama-3.1:8B, and Qwen-2.5:7B, kernel-managed retrieval beats an unmanaged Mem0 backend on identical storage by 2.4–4.0 points on a 5-point personalization scale (e.g. profile usage 1.05→4.69 on GPT-4o, all p < 10⁻¹⁸), with similarly large gains vs standard RAG injection. Against full unfiltered context concatenation it statistically matches two of three models while cutting end-to-end latency 15–61% and shrinking prompts/tokens/cost. Ops takeaway for Tal’s multi-bot fleet: centralize memory policy in the harness kernel so personalization and injection control are system services, not each agent’s private RAG glue.

## Agent harness

### ChurnBench: A Drift-Aware Benchmark Demonstrating That Refresh Scheduling, Not Cache Age, Governs Staleness in Agentic AI

https://arxiv.org/abs/2609.11515

Singh and Priyam open ChurnBench for the production failure mode retrieval benches miss: enterprise facts keep changing (licenses, offboarding, prices, contracts), so an answer that was correct at retrieve-time can be wrong at evaluate-time. The benchmark generates a four-source enterprise fabric as a timeline with an append-only ground-truth ledger; gold answers come from the ledger, never live stores, and each case is resolved at both retrieve and evaluate timestamps so freshness errors separate cleanly from reasoning errors. Punchline: under scheduled refresh, cache age does not predict staleness—freshness errors were 7 / 4 / 4 at 1 / 14 / 28-day cache ages because TTL bounds drift; disable tiered refresh and 28-day freshness errors jump 4→45 while one-day stays flat. Sweep TTL against each entity’s change rate, not drift-window length. Code, data, and harness released. Harness implication for Tal: agent correctness over live stores is a refresh/TTL control-plane problem, not only a retrieval-quality problem.

### terms.txt: A Consent and Compensation Protocol for Agentic Web Access

https://arxiv.org/abs/2609.11152

Chowdhury argues the open web’s crawler-for-referral bargain is breaking under AI agents: automated clients dominate traffic, training dominates Cloudflare-classified crawling, and top AI platforms fetch thousands of pages per visitor returned. robots.txt cannot express identity, purpose, terms, or price and is easy to circumvent; newer controls are mostly proprietary CDN features. He specifies terms.txt—a robots.txt-style per-path, per-purpose machine-access policy—plus an origin-enforced exchange using Web Bot Auth signatures, signed intent, delegation tokens, HTTP 402 negotiation, and signed receipts, with a clear split of what the protocol can enforce, audit, or leave to contract. A dependency-free implementation adds only 0.20–0.65 ms per request on one vCPU. Product/harness read for Tal: as browsing agents leave the chat box, origin-enforced agent identity and paid/consented access become part of the tool boundary—not an afterthought robots.txt.

### BenchShield: Formal Model-Backed Instrumentation for Reward Integrity in LLM-Agent Evaluation Infrastructure

https://arxiv.org/abs/2609.11028

Zheng et al. treat LLM-agent benchmarks as interactive infrastructure that agents can reward-hack—observing state, calling tools, editing workspaces, and optimizing the score trajectory instead of the intended task. Existing defenses (task patches, prompt instructions, post-hoc detectors) do not give reusable evidence that a concrete run stayed inside its evaluation boundary. BenchShield adds a model-backed instrumentation layer: a finite lifecycle model of reward-relevant events, static phase-aware taint analysis that exposes hacking paths before a run, and runtime infrastructure-side attribution that emits evidence-backed claims. On BenchShield Trajectories (456 human-adjudicated runs from >31k public agent trajectories across three benches) it lifts full-chain recall 23–94%→77–100% and same-vector coverage 16–56%→43–78% vs an agentic hackability scanner, cuts per-task cost up to 65%, and hits 96% runtime reward-hack detection accuracy. Relevant wherever Tal runs agent evals or harness bake-offs: score integrity needs infrastructure instrumentation, not only “don’t hack” prompts.

### Engineering Reliable Commit Gates for Agentic AI: Cost-Aware Verification Portfolios under Common-Mode Data Failures

https://arxiv.org/abs/2609.10969

Zheng, Li, Yao, and Long study the failure mode where agentic commit gates add verifiers that still share the same upstream fault. VP-CONTROL is a runtime-assurance design plus deterministic benchmark (48 templates → 2,880 scenarios, six fault regimes) that separates verifier-model diversity from evidence-source diversity in a fixed-call 2×2. On frozen proposals from two local actor families, cross-model vote over shared evidence still approves 62.9% of unsafe proposals vs 22.9% with an independent evidence source—a 40.9-point source effect dwarfing the 11.3-point model-diversity effect. A portfolio controller using only deployment-observable metadata reaches ~1.9% unsafe execution and 38.2% automated safe coverage at a nominal 5% per-task target; matched-budget portfolios beat fixed policies, but transfer to unseen fault families stays risky (16–26%) and a FinQA check fails to reproduce the source effect with small verifiers. Live HTTP/SQLite study: after-check races defeat verifier-only gates; full atomic guards + idempotent request IDs are what actually stop unsafe/duplicated effects. Sharp Sentinel/commit-gate lesson for Tal: diversify evidence lineage and enforce at commit time—do not assume a second model looking at the same tainted view is a safety win.

### Decoupling Readiness from Release for Tail-Aware Scheduling of Agentic LLM Workflows

https://arxiv.org/abs/2609.10964

Feng et al. observe that agentic LLM workflows are sequences of model turns interleaved with tools, so end-to-end latency depends on when ready turns are released—not only on inference speed. Eager release under contention accumulates released-but-unfinished work that can no longer be reordered, inflating tails. They propose a tail-risk-aware release scheduler that jointly picks which ready turn to release and how much unfinished released work to allow, using a mean–CVaR objective, online turn-work estimates, and a work budget that adapts to queue pressure. On real software-engineering agent traces across multiple LLMs and arrival rates, it matches eager release under light load and cuts P95 workflow flow time under contention by up to 3.50×. Practical harness note for Tal’s multi-agent / multi-turn fleet: treat turn release as a controllable scheduler, not an automatic side effect of “tool returned.”

### A2ABreak: Systematic Security Analysis of the A2A Protocol

https://arxiv.org/abs/2609.10871

Lotfi, Rahman, Karim, and Bertino deliver the first systematic security analysis of the Linux Foundation Agent2Agent (A2A) protocol—the emerging horizontal layer for cross-org agent discovery, auth, and task delegation alongside MCP for tools. A2ABreak uses an LLM-assisted extraction of a verified finite-state machine from the natural-language spec (37 states / 76 transitions from 929 formalized statements), then adversarially verifies under a full-compliance assumption. Result: 11 new vulnerabilities exploitable by a specification-compliant adversary with no implementation bug—including cross-client context injection via unprotected context IDs, credential harvesting through multi-hop identity loss in delegation chains, and exfiltration via rogue agents advertising unattested capabilities. Method beats a zero-shot LLM-over-spec baseline (0 confirmed findings) at 73.3% precision / 84.6% F1 vs expert review. Must-read for anyone wiring multi-agent protocols into a harness: treat A2A as an attack surface whose bugs live in the spec’s state machine, not only in your glue code.

## LLM security

### DriftNet: A Dual-Head Trajectory Transformer for Detecting and Localizing Prompt Injection in LLM Agents

https://arxiv.org/abs/2609.10892

Pinjari and Saint-Germain follow yesterday’s AgentDrift benchmark with DriftNet, the companion detector: when indirect prompt injection succeeds, the compromise is visible as a benign tool-call prefix, a poisoned observation, then attacker-serving actions—and operators need where it entered, which steps it corrupted, and whether poison was resisted. DriftNet is a dual-head trajectory Transformer (<2M trainable params over a frozen sentence encoder + four identity-free world features) that in one forward pass classifies the whole trajectory and labels every step benign / injection point / hijacked / failed injection—no access to the agent’s model. On AgentDrift’s task-disjoint split (12,536 trajectories / 71,024 steps) it hits trajectory F1 0.983, exact injection-point recovery on 98.7% of attacked traces, hijacked-span IoU 0.979, zero flags on 218 resisted attacks, and only 2.9% flags on hard negatives; partial-hijack / delayed-execution recall jumps to 98.6% / 93.2% vs 11.1% / 17.1% for a surface baseline. Immediate monitor upgrade for Tal’s agent fleet: step-labeled drift detection on logged tool trajectories, not only binary “was this run bad.”

### No-Box Vulnerability Analysis: Description-only Detection of Indirect Prompt Injection Vulnerabilities in MCP Servers

https://arxiv.org/abs/2609.10854

Zhang et al. (ASU-flavored, incl. Shoshitaishvili / Doupe) define no-box vulnerability analysis: third-party auditors get neither system access nor runtime interaction—only functionality metadata (intended inputs, outputs, side effects) that constrains the implementation space. Hypotheses are those that would hold across all implementations consistent with that metadata, to be validated later when access appears. Prototype MCPSEC audits Model Context Protocol servers for indirect prompt-injection surfaces using only the tool metadata exposed at registration. On 20 widely deployed MCP servers / 177 tools (95 human-confirmed vulnerable), MCPSEC flagged 143 tools and recovered 94 of 95 verified vulns (98.9% recall) vs an LLM baseline at 80/95 (84.2%), each with a hypothesized vuln plus exploitation technique. Highest-priority security item for Tal’s MCP/tool lane: you can red-team connector surfaces from the tool schema alone—before granting a sandbox.

### Architecting the Secure AI-SOC: A Neurosymbolic Framework for Pipeline Integrity and Threat Mitigation

https://arxiv.org/abs/2609.10707

Gazani et al. target the AI-SOC failure mode where LLMs ingest threat intel/logs and adversaries run multistep “promptware” kill chains via indirect prompt injection (log poisoning) that hijacks operational logic. Purely deterministic defenses are fast but semantically blind; purely neural checks are slow and probabilistic. Their neurosymbolic defense-in-depth stack: (1) customized SIEM decoders as a deterministic ingestion pre-filter that structurally sanitizes volumetric padding and signature injections at the edge; (2) NeMo Guardrails enforcing semantic boundaries with self-checking validation on structured SIEM alerts before the LLM sees them; (3) closed-loop telemetry that surfaces thwarted attacks to HITL on the SOC dashboard. Evaluated against diverse injections mapped to MITRE ATLAS, they argue the combo dismantles the promptware chain by bounding LLM stochasticity with verifiable constraints. Concrete architecture pattern for Tal wherever agents read untrusted logs/tool output: sanitize at ingest, guardrail before the model, and make blocked attacks visible—not silent.

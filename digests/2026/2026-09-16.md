### 6. ByteByteGo — Do LLMs Have the Memory of a Goldfish? [HIGH]
Primary link: https://blog.bytebytego.com/p/do-llms-have-the-memory-of-a-goldfish

Clear systems primer on why chatbots “remember”: **weights ≠ personal memory**. Trained memory (parameters) holds general patterns; **working memory** is the context window (system/dev instructions, history, retrieved docs, tools, preferences, summaries, output budget)—a desk that clears between calls; **persistent memory** lives in app-side DBs/vector stores/profiles and is re-injected each turn. Stateless Messages APIs require the client to resend history; server-managed conversation IDs only reconstruct context—they don’t give the model a private diary. Cost math: ~1k tokens/round → request N processes ~N×k cumulative input (10 rounds ≈ 55k tokens processed for ~10k visible). Large windows don’t fix recall (**context rot**); when full, apps drop oldest turns, roll windows, or **compact/summarize** (lossy—repeated summary-of-summary drifts). Extension stack: sliding window, conversation summarization, **structured entity extraction** (prefs, decisions, IDs), vector retrieval with metadata filters, long-term user profiles with timestamps/confidence, cross-session write→store→select→inject. Punchline: “memory quality depends at least as much on surrounding architecture as on the model.” Direct Tal product read — **HIGH** for Grok Bot / agents: application-layer memory (lifecycle-tagged writes, cue→source reconstruction, profile vs session) is the product, not bigger context; pairs with Tue Cursor Projects shared memory and recent LifeFuse-Mem / CueMem / AIM papers.

## Agent memory

### GraMRAG: Orchestrating Multi-Agent Multi-Step Reasoning via Graph Memory with Reinforcement Learning

https://arxiv.org/abs/2609.14066

Zhongyu Wang argues multi-agent RAG still fails on deep multimodal questions because retrieval is shallow and agents go “state blind” across steps. GraMRAG adds a dynamic multimodal memory graph: vision–text bridged ReAct-style tool use crops multi-scale entities, while agent reasoning is stored as a DAG of action–observation edges to cut redundant retrieval. Topology-Aware Policy Optimization (TAPO) uses graph topology for critical-path credit and node pruning across long trajectories. On hard multimodal benches it claims SOTA long-horizon reasoning vs prior multi-agent RAG. Memory design read for Tal: treat multi-step agent RAG state as an explicit DAG memory—not a flat chat buffer—and train with topology-aware credit so retrieval doesn’t reset every hop.

### Navigating Sparse Evidence: Agentic Visual RAG via Explicit Context Selection and Consolidation

https://arxiv.org/abs/2609.15800

Shen, Yan, Wu, Wang, WU, Yin, and Cao target Visual RAG over page images: answer evidence is sparse (tiny crop or spread across pages), and agentic explorers often answer from noisy trajectories or lossy text memories instead of an organized image set. SCoRE (Selection and Consolidation for Robust Evidence) keeps a bounded textual ledger of query-relevant observations + source pointers during exploration, then at termination reloads original images, consolidates them into a logical sequence, and answers with claim→image links—decoupling final reasoning from trial-and-error. Training mixes filtered cold-start trajectory distillation with evidence-aware RL rewarding coverage, consolidation compactness, and correctness. Agentic RAG pattern for Tal’s doc/vision agents: separate explore vs answer contexts; persist pointers, reload pixels for the final pass.

### ShopEase: A Generative AI-Based Multi-Agent Framework for Intelligent Enterprise Customer Support Using Hybrid Retrieval-Augmented Generation

https://arxiv.org/abs/2609.13856

Tiwari and Kumar ship ShopEase, a six-agent enterprise support stack (Intent, CRM, Memory, Hybrid RAG, Escalation, Supervisor) with local LLaMA 3.2 via Ollama. Hybrid retrieval mixes FAISS + BM25; policy category is inferred from retrieved docs rather than a fixed intent→policy map. On 2,632 held-out queries across Refund/Return/Shipping/Cancellation/Damaged/Unknown, FAISS-only hits 85.37% (2,247 correct) and Weighted RRF 85.07%; BM25-only only 55.74%. Cross-encoder rerankers hurt (83.24% / 81.88%) and add latency; McNemar finds FAISS ≈ Weighted RRF, both beat Fair RRF and cross-encoder setups. Unknown remains the error sink. Product RAG note for Tal: on this support corpus dense retrieval wins—don’t assume hybrid+rerank is free accuracy.

### The Attribution-Compression Frontier in Retrieval-Augmented Generation

https://arxiv.org/abs/2609.14245

Deepanshu Mody shows context compression for RAG is usually scored on answer quality alone, missing citation attribution. Under a fixed generator and NLI entailment evaluator on ASQA/QASPER, he compares reranking, extractive selection, abstractive summarization, token pruning, and extract–cluster–rewrite. On ASQA at nominal 0.25 budget (achieved ~0.08 compression), a RECOMP-style compressor’s citations score 0.86 precision vs its own summaries but only 0.12 vs source spans under a re-attributability protocol; claim verification after source recovery shows unsupported rate 0.88 vs 0.17 when checking summaries. Extractive selection’s grounded precision stays ~0.43–0.49 as budgets shrink while answers degrade. Caveat: estimates depend on a shared NLI model without human calibration. RAG eval rule for Tal: score citation→source, not citation→summary, when you compress context.

### OrchSLM: Probing the Dynamics of Small Language Model Orchestration

https://arxiv.org/abs/2609.13470

Zhang and Yao note SLMs are attractive for agentic pipelines (latency, privacy, cost) but small context windows limit long-horizon interactive orchestration (verify/debate loops). OrchSLM studies a non-interactive alternative: heterogeneous SLMs independently emit candidates; a router orchestrates cached samples without further model calls. The framework unifies existing non-interactive methods and exposes design knobs—task structure, model-pool composition, multi-agent consensus—as controllable parameters, probing how orchestration behavior emerges. Context-window / agent-orchestration item for Tal when packing SLM fleets: prefer cached multi-sample routing over interactive multi-turn when windows are tight—and treat pool composition and consensus rules as first-class harness knobs.

### BusMA: A Bus Communication Substrate for Multi-Agent Systems

https://arxiv.org/abs/2609.15054

Peng, Zhang, Wang, and Aletras attack multi-agent communication limits of Hierarchical Manager–Worker and Router message-passing (no peer consult; misroutes amplify errors). BusMA borrows computer-bus design: shared channel with registration, routing, and shared memory management; workers keep local memory, use tools, and post intents (discussion, challenge, guidance, request for explanation) while a Chair monitors shared memory for convergence. On 13 visual/math/knowledge tasks with two frontier LLMs, BusMA beats HMW and RMP baselines. Keyword hit is “shared memory management” (bus/comms substrate, not episodic long-term agent memory)—kept with that caveat, useful for Tal’s multi-agent harness wiring.

## Agent harness

### Asclepius: An Adaptive Harness for Long-Horizon Clinical Agents

https://arxiv.org/abs/2609.13543

Chang Yuan, Zhang, Kim, Luo, and Rajpurkar use the Clinical Environment Simulator (CES)—an agent runs a full ED shift under continuous time/resource pressure—to show long-horizon failures that short benches miss: agents often diagnose correctly yet miss complete/timely critical actions. They count three coupled failure modes per trace (instruction-adherence drift, treatment incompleteness, severity-equity timeliness gap) and ship Asclepius: a self-evolving harness that rewrites the operating manual between shifts from trace feedback, an externalized clinical skills library, and three isolated subagents partitioning the patient queue. On held-out batches never seen during harness evolution, critical-action correctness rises 22% (p=0.024) vs a strong baseline while diagnosis holds; full ten-batch set: +25% critical actions, +13% timeliness; five LLM judges × three families agree. Gains need all three components together. Highest-signal harness paper in this fire for Tal: evolve the harness from traces, externalize high-stakes skills, partition long queues—don’t only swap the base model.

### Toward Self-Adaptive Physical AI: Can LLM Agents Manage Long-Horizon Physical Tasks?

https://arxiv.org/abs/2609.13436

Kaushik, Tan, and Yu ask whether LLM agents can run long-horizon physical tasks zero-shot and adapt when the environment shifts—without the data/retraining RL usually needs. Their multi-agent loop integrates planning, tool calling, observation, and verification on agricultural management vs RL agents under weather regimes. Zero-shot LLM agents match RL under the trained weather pattern and adapt better than RL under shifted weather. Physical-agent harness pattern for Tal: pair plan→tool→observe→verify for embodied/long-running control, and expect LLM agents to transfer across environment shift better than frozen RL policies when you can’t retrain.

### When Malicious Instructions Persist: Persistent Memory Poisoning Attack on Harness-Based Agents

https://arxiv.org/abs/2609.13889

Huang, Zhang, and Jia show harness memory is an attack surface: PMPA (Persistent Memory Poisoning Attack) plants malicious instructions in benign external sources so the victim writes them into persistent memory without touching the agent framework; later sessions retrieve the poison, trigger extra actions, and leak privacy. On OpenClaw and Claude Code across backbones, modalities, and triggers, average Injection Success Rate / Cross-session ASR are 73.7%/55.5% (OpenClaw) and 66.9%/81.7% (Claude Code) while benign task performance holds. Prompt-level defenses cut injection in many settings but barely help once memory is already poisoned. Must-read for Tal’s harness+memory stack: treat memory writes from tool/web content as untrusted; defend at write time and assume post-poison cleanup needs more than a system-prompt patch.

### Why LLM Agents Collapse Without Oversight: The Enforcement Gap as the Mechanism Behind Emergence World Failures

https://arxiv.org/abs/2609.15293

Yuhang Wang explains Emergence World-style unsupervised multi-agent collapses (crime, starvation, conformity) without an external attacker: Reflexion-style agents already detect dangerous steps via self-critique, but there’s no path from audit to action—the enforcement gap. Closing it is a single conditional check (<20 LOC) that cuts attack success >4× across frontier models, all five major agent frameworks, and an independent bench. Formal claim: when enforcement probability ≈0, detection quality is irrelevant. Two compounding modes—unreliable auditors and unparseable verdicts—cover Emergence World collapses; a GRPO-trained enforcement controller handles ambiguity. Proposes a three-requirement Audit Enforcement Spec missing from every deployed framework today. Harness rule for Tal: wire critique→gate→act; logging “I noticed a problem” without a hard stop is not safety.

### Salesforce Koa: An Enterprise Language Model for Agentic Tool Use

https://arxiv.org/abs/2609.15066

Chen et al. (Salesforce, 25 authors) post-train open-weight Nemotron-3-Super-120B with GRPO into Salesforce Koa for enterprise tool use/agentic work—no customer data. Distinctive piece: a simulation-to-reward pipeline that expands workflow specs into persona-conditioned multi-turn tasks with rewards grounded in successful tool use; enterprise specs use Agent Script (Agentforce), public tool domains synthesize workflows, same machinery drives GRPO. Gains clearest on multi-turn tool use across public tool-use, agentic-reasoning, and CRM benches—beats the open base and a strong proprietary baseline, still below top frontiers. Spec-driven RL template for Tal’s enterprise agents: generate multi-turn tool trajectories from declarative workflow specs, reward task resolution, don’t only SFT on chat.

### The Agentic Company OS: Substrate Inversion for Sustained Enterprise Agent Deployment

https://arxiv.org/abs/2609.13334

Larsen and Moghaddam’s position paper diagnoses why enterprise agents demo well then stall in production: they reason over data shaped for humans/apps, not for LLMs. Proposal—substrate inversion: rebuild the cognitive substrate agents read as working context around LLM-matched representations (Markdown as today’s stand-in), keep schema translation at the action boundary. Two mechanisms: context-bandwidth asymmetry (one-pass connected prose vs field-by-field typed access) and cross-loop coupling (action/skill/policy loops only compound on one shared substrate). Four-layer frame (Data, Knowledge, Intelligence, Governance) plus Sync Agent and per-skill trust gradient make audit structural. Mentions indirect prompt injection on the compile path as a risk. Architecture brief for Tal’s multi-day agents: invest in the shared substrate agents read—not only better planners—if you want retention and compounding improvement.

## LLM security

### SkillSecurer: Detecting and Patching Prompt-Injection Vulnerabilities in AI Agent Skills

https://arxiv.org/abs/2609.14079

Mecca, Verna, Bouchari, Jha, and Mellia target prompt injection in agent skills (reusable instructions/scripts/config). SkillSecurer is a fully agentic red/blue loop: red agent writes context-compatible injections across nine threat types with recorded edits; blue agent analyzes full skill packages, grounds evidence, and proposes patches; a verifier scores against recorded injections. With its best backend it’s the only scanner hitting 100% injection detection in their comparison; on popular skills.sh skills, >17% show latent vulnerabilities, and some trigger real incidents when run. Agent-skill supply-chain item for Tal: scan/patch skills like dependencies—don’t install unverified skill packs into production agents.

### ActGuard: Pre-execution Action Auditing against Indirect Prompt Injection in LLM Agents

https://arxiv.org/abs/2609.14987

Wang, Gu, Wang, Yang, Li, and Yin defend tool-using agents against indirect prompt injection without blanket over-sanitizing. ActGuard audits pre-execution: builds a local tool prior for the next step (no frozen plan), contrastively flags tool/parameter deviations from that prior, localizes malicious spans, masks only confirmed spans, and regenerates the action. Claims ASR cut to SOTA-defense levels while task utility stays near the no-attack setting; code released. IPI defense pattern for Tal: gate on action deviation from a local prior, not on “is this content scary,” so you keep planning flexibility.

### PIDS-Bench: Evaluating Prompt-Injection Detectors Under Over-Defense, Obfuscation, and Distribution Shift

https://arxiv.org/abs/2609.15017

Shire and Kim argue prompt-injection detector evals that report only in-distribution F1 hide operational failure—especially benign false positives. PIDS-Bench jointly scores attack detection and hard-benign FPR at fixed thresholds across ID, hard-benign lookalikes, obfuscation, and domain/structure shifts for seven detectors plus a rule baseline. A detector with F1>0.98 on the held-out split still misclassifies ~1/3 of an externally-sourced benign security-adjacent subset. Across threshold sweeps and five seeds, no internal detector hits F1≥0.95 and hard-benign FPR≤0.10 together on that stress set. Hard-negative augmentation nearly kills over-defense on curated stress inputs but leaves externally-sourced FPR high—“provenance-sensitive over-defense.” Detector ops rule for Tal: refuse to ship on ID F1 alone; require hard-benign FPR under distribution shift.

### Confuse the Model, Control the Flow: Understanding and Mitigating Privacy Leakage from LLM Agents with Information Flow Control

https://arxiv.org/abs/2609.14003

Shim, Karim, Jakkula, Zhou, Liu, Wang, and Li show personal LLM agents with private data leak even without classic prompt injection when enforcement lives inside the same LLM context the adversary steers. Three attacks—Collaborative Workspace Lure, Semantic Obfuscation (omit rather than write), Channel Decoupling—beat the attacks prior prompt defenses were built for. FLOWSEAL moves confidentiality to a tool-level interceptor outside LLM context, using data provenance and an IFC lattice with controlled declassification. Across three benches, five prompt baselines, eight attacks (incl. live MCP tool calls), leaks fall near zero (e.g. Collaborative Workspace Lure 52.2%→0.5%) with utility preserved, backend-agnostic. Privacy architecture for Tal’s personal agents: enforce disclose/deny at the tool boundary with provenance labels—don’t ask the same model to judge the attack it’s reading.

### Authorization Architectures for Tool-Using AI Agents

https://arxiv.org/abs/2609.15906

Surapani, Kakitapelli, Morampudi, and Padi review authorization for tool-using agents (APIs, DBs, browsers, MCP). They organize a principal hierarchy (human → operator → orchestrator → sub-agent → tool) and five layers: identity/credentials, delegation/scope across hops, runtime JIT authorization at PEPs, prompt injection as authorization bypass, and audit/provenance/non-repudiation. From ~180 candidates → 89 primary sources (2023–2026), they propose seven structural requirements, a four-layer reference architecture, three deployable configs, and call out runtime enforcement + aggregation bounds as the main open gaps. AuthZ checklist for Tal’s MCP/tool agents: every consequential call must be attributable, scope-bounded to what the human delegated, and contestable after the fact.

### Divide, Consult, Conquer: Capability Laundering Through Aligned LLMs

https://arxiv.org/abs/2609.15383

Russinovich, Bullwinkel, Severi, Ovadiuc, and Salem (Microsoft-style authorship) show capability laundering: a weak unaligned orchestrator splits a harmful task into benign-looking subproblems, consults a strong aligned frontier on each, and composes answers locally—no single response is the harmful task (unlike classic jailbreaks). On CyBench, Gemma-4-31B recovers 8/14 candidates with GPT-5.5 and 7/9 with Opus (vs 2/21 and 4/15 for Gemma-4-12B); BountyBench similar uplift; on an 8-step hypothetical CBRN bioweapon chain, consultation lifts Gemma-4-31B mean rubric score 62.3→83.1/100. Defense gap: refusing a monolithic harmful ask doesn’t stop frontier capability from transferring across many allowed micro-queries. Red-team note for Tal: evaluate multi-turn consult-and-compose attacks, not only single-prompt jailbreaks.
